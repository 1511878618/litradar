# Litradar 0.4：每日阅读与恢复流程

## 抓取失败与漏抓

- **覆盖情况 → 只重试本刊**：重新请求选中的期刊，合并回正在浏览的批次。其他期刊、原有文献、首次发现时间、补收录标记和覆盖记录保留。重试失败时保留之前的可用记录并注明失败原因。
- **工具栏 → 重试失败期刊**：处理当前批次的失败来源，不重抓成功期刊。
- **工具栏 → 补齐／回查迟到**：补齐最近几天缺失的日报，同时回查已有日期中迟到的文献。新增条目标记“补收录”，按来源提供的发表日期归档；重复 DOI 不重复添加。
- **设置 → Litradar → 自动补齐与迟到回查**：自动任务开启时每天执行一次。回查天数可设为 1–7，默认 3；可关闭自动回查，仍可手动执行。保持 Obsidian 打开；系统后台任务独立管理。

Crossref 按页读取，默认每页 200、最多 20 页；`journals/<slug>.yaml` 可设 `rows`（1–1000）和 `max_pages`（1–50）。分页失败或达到上限会在覆盖原因中显示已读取数量，不将截断结果当作完整收录。超过 offset 上限时需缩短查询窗口。备用来源仍标注“仅元数据”，日期未在官网核实；回查范围之外的延迟记录需要手动补查。

```bash
litradar repair --vault /path/to/vault --run-id 2026-11-06 --journal "Science"
litradar repair --vault /path/to/vault --run-id 2026-11-06
litradar maintain --vault /path/to/vault --days 3 --no-llm
```

## 跨批次查找

展开 **跨批次文献库**，选择“最近一周／最近一个月／全部历史”，点击“加载／刷新文献库”。日期范围按日报日期计算。可组合中文／英文／摘要／作者／DOI 搜索，以及期刊、主题、文献类型和 Zotero 阅读状态筛选。按 DOI 去重，展示文献出现过的日期。每次展示 50 篇，可继续加载。

面板与日报共用引擎生成的中文标题、中文解读和推荐理由，英文原题保留。中文标题翻译失败时回退英文。旧批次可以从已有缓存构建展示数据，不需要重新联网翻译：

```bash
litradar library-rebuild --vault /path/to/vault
```

没有缓存译文的历史文献仍显示原题，需要重生成该批次后才能补翻译。刷新文献库可看到新生成的展示数据。

## Zotero 状态与 PDF

每张卡片的“刷新入库／PDF 状态”会实际查询 Zotero：未入库、已入库但无 PDF、已有 PDF 附件、检查失败等结果直接保留在卡片。保存或下载操作期间显示进度，完成后自动检查；下载后短暂轮询仍未发现附件时会提示继续检查，不承诺已成功下载全文。

继续使用已有 **Reading List + Litradar Zotero Bridge 0.2.0**，本次无需安装新的 Zotero 扩展。阅读状态由 Reading List 管理。Zotero 必须打开；是否能获取全文取决于 Zotero 可找到的来源和访问权限。

## 推荐反馈

卡片上选择 **相关／不相关／减少这类推荐／撤销反馈**。反馈写入 `.litradar/state/feedback.json`，立即更新面板展示数据；Markdown 日报在重生成时同步。不会删除文献或修改 Zotero 阅读状态。

当前采用可解释的本地排序调整：相关 +0.2，不相关及直接减少 -0.3；与“减少这类推荐”的英文标题至少共享三个有效词、Jaccard 相似度达到 0.25 的条目 -0.15，最终分数限制在 0–1。属于排序偏好，不是训练新模型，也不替代研究画像。撤销反馈会取消对应调整。

## 预印本与正式版

引擎读取 Crossref 的版本关系，以及 bioRxiv/medRxiv 提供的正式发表 DOI。存在明确关系时显示关联 DOI 和证据来源；不凭标题相似自动合并。正式版已被本地收录后，对应预印本不再重复置顶，正文仍保留两篇。

原来的 Zotero 条目和 Reading List 状态完整保留，卡片可展示关联版本已有的阅读状态；不会自动覆盖正式版的状态，也不会迁移附件。缺少来源关系数据时，不会猜测关联。

## 数据与恢复

新增 `runs/<run-id>/presentation.json`（共享展示数据）、`state/feedback.json`（反馈）、`state/versions.json`（版本关联）。原始 store、seen 和阅读状态由原有流程管理。重试／回查和反馈写入均受 vault 锁保护。
